# FixLens · 고정 카메라 공간 정리 프로토타입

FixLens는 카메라를 고정해 책상 같은 작은 공간을 스캔하고, 물건의 배치를 저장했다가 청소 후 화면 안내를 보며 다시 놓을 수 있는 모바일 웹 프로토타입입니다. 카메라 화면에서 스캔할 사각 영역을 직접 조정할 수 있습니다. **공간 스캔 시작**을 누르면 선택 영역을 3×3 타일로 나눠 분석하고, 처리 완료 타일 수와 물체 후보를 보여줍니다. 확인한 배치를 이 브라우저에 저장하거나, 미니멀·작업 효율·아늑하게 중 한 가지 스타일을 골라 AI가 새 배치안과 이동 순서를 제안하게 할 수 있습니다.

## 저장한 배치로 되돌리기

1. 정리 전 카메라를 고정하고 책상 영역을 스캔합니다. 물건 이름과 포함 여부를 확인한 뒤 **현재 배치 저장**을 누릅니다. 같은 이름의 물건이 여럿이면 각각 구분되는 이름으로 수정해야 합니다.
2. 배치를 불러올 때 같은 브라우저에서 같은 공간 이름을 사용합니다. 카메라를 저장할 때와 같은 각도로 고정하고 책상 영역을 맞춘 다음 **저장한 배치로 되돌리기**를 누릅니다. 물건을 책상에서 모두 치운 상태여도 다시 스캔할 필요는 없습니다.
3. 카메라 화면의 점선 목표를 보며 물건을 하나씩 놓고 **놓았어요 · 다음 물건**을 누릅니다. 이 경로는 사용자가 이동 완료를 직접 확인하며, 자동 물체 추적이나 정확한 3D 공간 고정을 하지 않습니다.

저장된 이름과 2D 위치는 공간 이름별로 해당 브라우저의 `localStorage`에 저장됩니다. 사진은 저장하지 않으며 **저장된 배치 삭제**로 지울 수 있습니다. 다른 브라우저나 기기로 자동 동기화되지 않습니다. 브라우저 저장 공간을 지우면 배치도 사라집니다. 카메라 각도·거리나 책상 영역이 달라지면 저장 위치와 실제 책상이 어긋날 수 있습니다.

## 동작 방식

1. 브라우저에서 COCO-SSD Lite MobileNet 모델을 Web Worker와 WASM으로 실행해 카메라 장면의 물체를 감지합니다.
2. 선택 영역만 3×3 겹침 타일로 나눠 분석합니다. 완료율은 `완료 타일 수 / 전체 타일 수`로 계산하며, 실패 타일은 다시 분석할 수 있습니다. 타일 완료는 선택한 이미지 영역의 처리 상태를 나타내며 공간이나 물체를 완벽하게 인식했다는 비율은 아닙니다.
3. Ollama 서버가 준비되어 있으면 선택 영역 이미지를 Mac으로 보내 `qwen3.5:4b`가 물건 종류·개수·상자 위치를 검토합니다. 브라우저 감지보다 결과가 늦게 올 수 있으며, 분석이 끝날 때까지 다음 단계 버튼을 잠시 잠급니다. 사용자가 후보를 직접 수정한 뒤에는 AI 응답이 목록을 덮어쓰지 않습니다.
4. 사용자가 물건 이름과 포함 여부를 확인하고 정리 스타일을 고르면, 같은 스캔 사진과 확정된 물건 위치를 `/api/plan`으로 보내 Ollama가 목표 중심 좌표·이동 순서·물건별 배치 이유를 생성합니다. AI가 배치안을 반환하지 못하면 임의 배치로 대체하지 않고 오류를 보여줍니다. 성공하면 카메라 화면에 점선 목표와 화살표가 나타나고, 물건을 하나씩 옮기도록 안내합니다.
5. 이동 안내는 현재 단계와 전체 진행률을 표시합니다. 안내 중 브라우저는 프레임 사이의 클래스·상자 겹침·중심 이동으로 같은 물건의 임시 `trackId`를 이어 붙이고, 안내 대상 상자를 강조합니다. 목표에서 같은 ID가 안정적으로 보이고 원래 위치에서 사라진 경우에만 완료 후보로 표시하며, 다음 단계로 넘어가려면 사용자가 확인을 눌러야 합니다. 건너뛴 물건은 완료로 세지 않고 안내 종료 시 개수를 알려줍니다.
6. 이동 중에는 안내 패널을 접어 카메라를 가리지 않고, 현재 물건과 진행률만 작은 손잡이에 표시합니다. 목표 위치에서 물건을 안정적으로 감지하면 확인 패널을 열어 다음 단계로 이어갑니다.
7. 카메라 켜기를 누르면 브라우저가 전체 화면과 가로 화면 고정을 요청합니다. 브라우저가 이를 지원하지 않거나 허용하지 않으면 세로 화면에서 가로 회전 안내를 표시합니다. 브라우저 정책상 자동 전환은 사용자 동작 이후에만 요청할 수 있고 기기별 지원 차이가 있습니다.
8. 가로 화면에서는 카메라 영상 밖 왼쪽에 스캔·카메라 조작과 상태 안내를, 오른쪽에 스캔 결과와 정리 단계를 두고 중앙을 영상 영역으로 남깁니다. 물체 목록만 패널 안에서 스크롤되며, 다음 단계 버튼은 목록을 끝까지 내리지 않아도 보입니다. 배치안 단계도 순서 목록만 따로 스크롤됩니다.

카메라를 켜면 브라우저가 WebXR `immersive-ar` 세션 지원 여부를 확인합니다. 지원 기기의 정리 안내 화면에는 **AR 위치 고정 테스트** 버튼이 나타납니다. 실행할 때 표면 인식(`hit-test`)과 AR 화면 위 조작부(`dom-overlay`)를 필수로 요청하며, 지원되지 않으면 카메라 안내로 돌아갑니다. 이 테스트는 AR 화면에서 표면을 탭해 링 마커 하나를 공간에 고정합니다. AR 세션 동안 일반 카메라 감지는 멈추며, 계획된 2D 배치 좌표를 AR 좌표로 자동 변환하거나 물체 윤곽을 함께 추적하지는 않습니다. 세션을 종료하면 이동 판정 상태를 초기화하고 카메라 감지를 다시 시작합니다.

물체 감지와 이동 관찰은 휴대폰 브라우저에서 실행됩니다. Mac의 Qwen 모델은 선택 영역의 물체 이름을 보완합니다. 브라우저와 기기 성능에 따라 타일 처리 속도가 달라집니다.

## 현재 범위와 한계

- 화면 강조는 픽셀 단위 외곽선이 아닌 사각 경계 상자입니다. COCO의 일반 물체 범주에 없는 물건이나 작은 물체를 놓치거나 잘못 분류할 수 있습니다.
- 스캔 진행률은 선택 영역을 나눈 타일 중 처리가 끝난 타일의 비율입니다. 공간이 완벽히 재구성되었거나 물체를 모두 찾았다는 뜻은 아닙니다.
- AI 배치안은 한 장의 사진과 2D 감지 상자를 바탕으로 목표 위치와 순서를 제안하는 프로토타입입니다. 실제 책상 깊이·물체의 물리적 크기·가려진 면·정확한 충돌 여부를 측정하지 않으므로, 제안 위치는 사용자가 확인해야 합니다.
- 화살표와 목표 위치는 카메라 영상 위의 2D 오버레이입니다. 카메라를 움직이면 안내가 실제 공간에 고정되지 않으므로 스캔부터 이동 완료까지 카메라와 책상을 고정해야 합니다.
- 물체 ID는 외형 인식 모델이 아니라 클래스·상자 위치의 휴리스틱 연결입니다. 짧은 가림 뒤 ID를 다시 잇도록 시도하지만, 같은 종류 물체가 가까이 있거나 이동 중 분류·상자가 크게 달라지면 ID가 끊기거나 바뀔 수 있습니다. 연결이 모호하면 자동 이동 완료를 막고 직접 확인을 요구합니다.
- AR 위치 고정은 지원 기기에서 hit-test로 사용자가 탭한 위치에 임시 링 마커를 고정하는 기술 확인 단계입니다. 계획된 물체·목표 좌표와 연동되지 않으며, AR 세션 중 물체 감지는 멈춥니다. 깊이, 가려진 물체, 여러 시점 간 정합, 실제 3D 공간은 재구성하지 않습니다.
- 로컬 AI 이름 보완 또는 새 배치안 생성 요청 시 선택 영역으로 자른 이미지 한 장이 Mac Ollama 서버로 전송됩니다. 전체 프레임과 원본 이미지는 저장하지 않습니다. 사용자가 **현재 배치 저장**을 누르면 이름·2D 위치만 해당 브라우저에 남습니다. AI가 만든 새 배치안은 현재 페이지 세션에서만 사용합니다.

## Mac에서 서버 관리

Finder에서 `FixLens Server.command`를 더블클릭하면 Mac 전용 웹 관리 화면이 브라우저에서 열립니다. 관리 화면은 별도 로컬 프로세스라 FixLens 웹 서버를 종료해도 계속 사용할 수 있습니다. 이 화면에서 웹 서버·Ollama·휴대폰 HTTPS 터널의 상태를 확인하고 각각 또는 전체를 시작·종료할 수 있습니다. 터널이 준비되면 QR과 휴대폰 주소가 같은 화면에 나타나며, 작은 화면에서는 QR이 서비스 목록보다 위에 배치됩니다. 최근 서비스 로그도 펼쳐서 볼 수 있습니다. 터미널 메뉴가 필요하면 `scripts/manage-server-menu.sh`를 직접 실행하세요.

필요한 것: Node.js 20 이상, Ollama, 그리고 프로젝트의 `dist/`에 포함된 COCO-SSD 및 WASM 모델 파일. Qwen 이름 보완을 쓰려면 모델을 한 번 받아야 합니다.

```sh
ollama pull qwen3.5:4b
```

웹 관리 화면은 `http://127.0.0.1:4174`에서 실행되고, FixLens 앱 서버는 `http://127.0.0.1:4173`에서 열립니다. QR은 휴대폰에서 FixLens 앱을 여는 주소이며 관리 화면 주소가 아닙니다. 관리자 서버는 loopback 주소에만 바인딩되어 휴대폰용 Cloudflare 터널로 외부에 노출되지 않습니다. Ollama가 이미 실행 중이면 상태를 표시하지만, 관리자가 시작하지 않은 전역 인스턴스는 **전체 종료**에서도 종료하지 않습니다. `cloudflared`를 사용할 수 없으면 웹 서버는 켜진 채 남고 QR은 표시되지 않습니다. Ollama를 사용할 수 없어도 브라우저의 기본 실시간 물체 감지는 동작합니다.

관리 화면의 **전체 종료**는 이 프로젝트에서 관리하는 HTTPS 터널, 웹 서버, Ollama를 종료합니다. 관리 웹 화면은 다시 서비스를 시작할 수 있도록 계속 실행합니다. 실행 로그와 PID 파일은 `.run/`에 저장되며 Git에는 포함되지 않습니다.

관리 화면의 **접속 기기와 진행 중인 작업**에는 FixLens 페이지를 열어 둔 브라우저가 최근 60초 안에 보낸 상태만 표시합니다. 브라우저 탭은 약 15초마다 임시 탭 식별자, 기기·브라우저 종류, 카메라 켜짐 여부, 현재 단계와 진행 수만 보냅니다. 이 상태는 서버 메모리에만 보관되며 IP 주소, 카메라 영상, 물건 이름은 기기 목록에 저장하거나 표시하지 않습니다. 휴대폰 브라우저가 백그라운드에서 멈추면 접속 중이어도 목록에서 잠시 사라질 수 있습니다.

휴대폰 스캔 요청은 `.run/web.log`에 시각, HTTP 응답 코드, 처리 시간, 요청 이미지 바이트 수만 기록합니다. 이미지, 물체 이름, 이미지 픽셀은 로그에 기록하지 않습니다.

## 휴대폰에서 카메라 테스트

휴대폰 브라우저의 카메라는 HTTPS 페이지에서 열어야 합니다. 관리 메뉴에서 **서버 시작 + 휴대폰 QR 열기**를 선택하면 터널 주소를 받은 뒤 외부에서 `/api/health`가 응답하는지 확인하고 QR 이미지를 Mac에서 엽니다. QR이 표시되면 휴대폰 기본 카메라로 비추고 링크를 눌러 접속하세요. 관리 메뉴의 상태 화면에는 외부 연결 확인 여부도 표시됩니다. 이미 서버를 켰다면 **휴대폰용 HTTPS 터널 시작** 또는 **휴대폰 접속 QR 열기** 메뉴를 쓸 수 있습니다. 이 기능은 `cloudflared`, Node.js 및 FixLens 웹 서버가 실행 중일 때 사용할 수 있습니다. 터널은 공개 접속 주소를 만들므로 필요할 때만 켜고, 사용을 마치면 메뉴에서 종료하세요. 터미널 명령으로 직접 실행할 수도 있습니다.

```sh
cloudflared tunnel --url http://127.0.0.1:4173
```

QR 이미지는 `.run/phone-access-qr.png`에 생성됩니다. 터미널에도 HTTPS 주소가 표시되므로 QR을 사용할 수 없으면 직접 입력하면 됩니다. Quick Tunnel 주소와 QR은 터널 실행을 다시 할 때 바뀌며, Mac과 서버 프로세스가 켜져 있을 때만 사용할 수 있습니다. 주소는 **상태 확인**이나 `.run/tunnel.log`에서도 확인할 수 있습니다.

휴대폰의 실시간 감지 프레임은 기기 안에서 처리합니다. Qwen 이름 보완을 위해 보내는 장면 이미지는 HTTPS 터널을 지나 Mac의 Ollama 서버에 도달하며, 이 앱은 원본 이미지를 저장하지 않습니다. Quick Tunnel은 개발용 공개 주소이므로 링크를 아는 사람이 접속할 수 있습니다.

## 설정

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `4173` | 웹 서버 포트 |
| `FIXLENS_HOST` | `127.0.0.1` | 서버 바인딩 주소 |
| `OLLAMA_URL` | `http://127.0.0.1:11434` | Ollama 서버 주소 |
