# FixLens · 고정 카메라 공간 정리 프로토타입

FixLens는 카메라를 고정해 책상 같은 작은 공간을 스캔하고, 정리 스타일을 고른 뒤 물건을 하나씩 옮기도록 안내하는 모바일 웹 프로토타입입니다. 카메라 화면에서 스캔할 사각 영역을 직접 조정할 수 있습니다. **공간 스캔 시작**을 누르면 선택 영역을 3×3 타일로 나눠 분석하고, 처리 완료 타일 수와 물체 후보를 보여줍니다. 스캔 후 미니멀·작업 효율·아늑하게 중 한 가지 배치 스타일을 고르면 물건별 목표 위치와 화살표 안내를 볼 수 있습니다.

## 동작 방식

1. 브라우저에서 COCO-SSD Lite MobileNet 모델을 Web Worker와 WASM으로 실행해 카메라 장면의 물체를 감지합니다.
2. 선택 영역만 3×3 겹침 타일로 나눠 분석합니다. 완료율은 `완료 타일 수 / 전체 타일 수`로 계산하며, 실패 타일은 다시 분석할 수 있습니다. 타일 완료는 선택한 이미지 영역의 처리 상태를 나타내며 공간이나 물체를 완벽하게 인식했다는 비율은 아닙니다.
3. Ollama 서버가 준비되어 있으면 선택 영역 이미지를 Mac으로 보내 `qwen3.5:4b`가 물건 종류·개수·상자 위치를 검토합니다. 브라우저 감지보다 결과가 늦게 올 수 있으며, 분석이 끝날 때까지 다음 단계 버튼을 잠시 잠급니다. 사용자가 후보를 직접 수정한 뒤에는 AI 응답이 목록을 덮어쓰지 않습니다.
4. 물건 이름과 목록을 확인하고 정리 스타일을 선택하면 화면 좌표 기준으로 배치안을 만듭니다. 카메라 화면에 점선 목표와 화살표가 나타나고, 물건을 하나씩 옮기도록 안내합니다.
5. 이동 안내는 현재 단계와 전체 진행률을 표시합니다. 안내 중 브라우저는 프레임 사이의 클래스·상자 겹침·중심 이동으로 같은 물건의 임시 `trackId`를 이어 붙이고, 안내 대상 상자를 강조합니다. 목표에서 같은 ID가 안정적으로 보이고 원래 위치에서 사라진 경우에만 완료 후보로 표시하며, 다음 단계로 넘어가려면 사용자가 확인을 눌러야 합니다. 건너뛴 물건은 완료로 세지 않고 안내 종료 시 개수를 알려줍니다.
6. 이동 중에는 안내 패널을 접어 카메라를 가리지 않고, 현재 물건과 진행률만 작은 손잡이에 표시합니다. 목표 위치에서 물건을 안정적으로 감지하면 확인 패널을 열어 다음 단계로 이어갑니다.
7. 카메라 켜기를 누르면 브라우저가 전체 화면과 가로 화면 고정을 요청합니다. 브라우저가 이를 지원하지 않거나 허용하지 않으면 세로 화면에서 가로 회전 안내를 표시합니다. 브라우저 정책상 자동 전환은 사용자 동작 이후에만 요청할 수 있고 기기별 지원 차이가 있습니다.
8. 가로 화면에서는 왼쪽에 스캔·카메라 조작을, 오른쪽에 물체 목록과 정리 단계를 두고 중앙을 카메라 영상으로 남깁니다.

카메라를 켜면 브라우저가 WebXR `immersive-ar` 세션 지원 여부를 확인합니다. 지원 기기의 정리 안내 화면에는 **AR 위치 고정 테스트** 버튼이 나타납니다. 실행할 때 표면 인식(`hit-test`)과 AR 화면 위 조작부(`dom-overlay`)를 필수로 요청하며, 지원되지 않으면 카메라 안내로 돌아갑니다. 이 테스트는 AR 화면에서 표면을 탭해 링 마커 하나를 공간에 고정합니다. AR 세션 동안 일반 카메라 감지는 멈추며, 계획된 2D 배치 좌표를 AR 좌표로 자동 변환하거나 물체 윤곽을 함께 추적하지는 않습니다. 세션을 종료하면 이동 판정 상태를 초기화하고 카메라 감지를 다시 시작합니다.

물체 감지와 이동 관찰은 휴대폰 브라우저에서 실행됩니다. Mac의 Qwen 모델은 선택 영역의 물체 이름을 보완합니다. 브라우저와 기기 성능에 따라 타일 처리 속도가 달라집니다.

## 현재 범위와 한계

- 화면 강조는 픽셀 단위 외곽선이 아닌 사각 경계 상자입니다. COCO의 일반 물체 범주에 없는 물건이나 작은 물체를 놓치거나 잘못 분류할 수 있습니다.
- 스캔 진행률은 선택 영역을 나눈 타일 중 처리가 끝난 타일의 비율입니다. 공간이 완벽히 재구성되었거나 물체를 모두 찾았다는 뜻은 아닙니다.
- 스타일 배치안은 화면 좌표에 배치하는 프로토타입 규칙입니다. 책상 깊이와 물체 크기, 사용 빈도, 실제 충돌 여부를 계산하는 AI 공간 최적화는 아닙니다.
- 화살표와 목표 위치는 카메라 영상 위의 2D 오버레이입니다. 카메라를 움직이면 안내가 실제 공간에 고정되지 않으므로 스캔부터 이동 완료까지 카메라와 책상을 고정해야 합니다.
- 물체 ID는 외형 인식 모델이 아니라 클래스·상자 위치의 휴리스틱 연결입니다. 짧은 가림 뒤 ID를 다시 잇도록 시도하지만, 같은 종류 물체가 가까이 있거나 이동 중 분류·상자가 크게 달라지면 ID가 끊기거나 바뀔 수 있습니다. 연결이 모호하면 자동 이동 완료를 막고 직접 확인을 요구합니다.
- AR 위치 고정은 지원 기기에서 hit-test로 사용자가 탭한 위치에 임시 링 마커를 고정하는 기술 확인 단계입니다. 계획된 물체·목표 좌표와 연동되지 않으며, AR 세션 중 물체 감지는 멈춥니다. 깊이, 가려진 물체, 여러 시점 간 정합, 실제 3D 공간은 재구성하지 않습니다.
- AI 보완이 켜져 있으면 선택 영역으로 자른 이미지 한 장이 Mac Ollama 서버로 전송됩니다. 전체 프레임은 서버에 보내지 않으며, 스캔 이미지와 공간 지도를 디스크에 저장하지 않습니다. 이름과 위치는 현재 페이지 세션에서만 사용합니다.

## Mac에서 서버 관리

Finder에서 `FixLens Server.command`를 더블클릭하면 터미널에 관리 메뉴가 열립니다. 처음 실행할 때 macOS가 확인 창을 띄우면 파일을 열도록 허용하세요. **서버 시작 + 휴대폰 QR 열기**를 선택하면 Ollama와 웹 서버를 시작하고 HTTPS 터널 주소가 준비되는 즉시 QR을 엽니다. 메뉴에서 상태 확인, 종료, 로컬 화면 열기, 로그 보기, 휴대폰용 HTTPS 터널 관리 및 접속 QR 재열기도 할 수 있습니다.

필요한 것: Node.js 20 이상, Ollama, 그리고 프로젝트의 `dist/`에 포함된 COCO-SSD 및 WASM 모델 파일. Qwen 이름 보완을 쓰려면 모델을 한 번 받아야 합니다.

```sh
ollama pull qwen3.5:4b
```

**서버 시작 + 휴대폰 QR 열기**는 Ollama가 응답하지 않을 때 Ollama를 실행한 뒤 FixLens 웹 서버와 HTTPS 터널을 시작하고, 터널 주소가 준비되면 QR을 엽니다. Ollama가 이미 실행 중이면 기존 인스턴스를 그대로 사용합니다. FixLens 웹 서버가 이미 켜져 있다면 같은 프로젝트에서 실행된 프로세스인지 확인한 뒤 관리 메뉴에 연결합니다. 웹 서버는 `http://127.0.0.1:4173`에서 열립니다. `cloudflared`를 사용할 수 없으면 웹 서버는 켜진 채 남고 QR을 열지 못했다는 안내가 표시됩니다. Ollama를 사용할 수 없어도 브라우저의 기본 실시간 물체 감지는 동작합니다.

**서버 종료**는 이 메뉴가 시작하거나 해당 프로젝트 프로세스임을 확인해 연결한 웹 서버와, 메뉴가 직접 시작한 Ollama만 종료합니다. 별도로 실행 중인 전역 Ollama는 종료하지 않습니다. 실행 로그와 PID 파일은 `.run/`에 저장되며 Git에는 포함되지 않습니다.

휴대폰 스캔 요청은 `.run/web.log`에 시각, HTTP 응답 코드, 처리 시간, 요청 이미지 바이트 수만 기록합니다. 이미지, 물체 이름, 이미지 픽셀은 로그에 기록하지 않습니다.

## 휴대폰에서 카메라 테스트

휴대폰 브라우저의 카메라는 HTTPS 페이지에서 열어야 합니다. 관리 메뉴에서 **서버 시작 + 휴대폰 QR 열기**를 선택하면 터널 주소가 준비되는 즉시 QR 이미지를 Mac에서 엽니다. 휴대폰 기본 카메라로 QR을 비추고 표시되는 링크를 누르면 접속할 수 있습니다. 이미 서버를 켰다면 **휴대폰용 HTTPS 터널 시작** 또는 **휴대폰 접속 QR 열기** 메뉴를 쓸 수 있습니다. 이 기능은 `cloudflared`, Node.js 및 FixLens 웹 서버가 실행 중일 때 사용할 수 있습니다. 터널은 공개 접속 주소를 만들므로 필요할 때만 켜고, 사용을 마치면 메뉴에서 종료하세요. 터미널 명령으로 직접 실행할 수도 있습니다.

```sh
cloudflared tunnel --url http://127.0.0.1:4173
```

QR 이미지는 `.run/phone-access-qr.png`에 생성됩니다. 터미널에도 HTTPS 주소가 표시되므로 QR을 사용할 수 없으면 직접 입력하면 됩니다. Quick Tunnel 주소와 QR은 터널 실행을 다시 할 때 바뀌며, Mac과 서버 프로세스가 켜져 있을 때만 사용할 수 있습니다. 주소는 **상태 확인**이나 `.run/tunnel.log`에서도 확인할 수 있습니다.

휴대폰의 실시간 감지 프레임은 기기 안에서 처리합니다. Qwen 이름 보완을 위해 보내는 장면 이미지는 HTTPS 터널을 지나 Mac의 Ollama 서버에 도달하며, 이 앱은 원본 이미지를 저장하지 않습니다. Quick Tunnel은 개발용 공개 주소이므로 링크를 아는 사람이 접속할 수 있습니다.

## 설정

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `4173` | 웹 서버 포트 |
| `FIXLENS_HOST` | `127.0.0.1` | 서버 바인딩 주소 |
| `OLLAMA_URL` | `http://127.0.0.1:11434` | Ollama 서버 주소 |
| `OLLAMA_MODEL` | `qwen3.5:4b` | 물건 인식 보완에 사용할 설치된 Ollama 비전 모델 |

서버는 이미지 요청을 JPEG, PNG, WebP 및 최대 2MB, 960×720으로 제한하고 한 번에 하나의 추론 요청만 처리합니다. 브라우저 요청 횟수도 제한합니다.

## 검증

```sh
node --check dist/app.mjs
node --test tests/camera.test.mjs tests/detection-state.test.mjs tests/frame-gate.test.mjs tests/detection-utils.test.mjs
node tests/model-smoke.mjs
```
